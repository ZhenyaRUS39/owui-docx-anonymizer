# Open WebUI DOCX Anonymizer

Серверный плагин для [Open WebUI](https://github.com/open-webui/open-webui): обезличивает
вложенные документы **до** того, как они попадут в модель, и восстанавливает оригинальные
значения в ответе, который видит пользователь.

Работает как обычный Open WebUI **Filter** (серверная функция) — никаких расширений
браузера, никакого трафика наружу: ядро и модель распознавания персональных данных
живут на том же хосте.

```
┌──────────────┐   вложение        ┌────────────────┐   метки      ┌──────────┐
│  Open WebUI  │ ─────────────────► │  docx-anon-    │ ───────────► │  LLM     │
│  (фильтр)    │                    │  service :8971 │              │ (ПДн нет)│
│              │ ◄───────────────── │  ядро upstream │  значения    └──────────┘
│  ответ + ПДн │   восстановление   │  + модель NER  │  (outlet)
└──────────────┘                    └────────────────┘
```

## Что это делает

| Шаг | Что происходит |
|---|---|
| `inlet` | Документ читается, обезличивается (ФИО, паспорт, адреса, ИНН, счета и т. д.), исходный файл вычищается из запроса, в текст подставляется обезличенная версия с метками вида `[ФИО_1]`, `[ПАСПОРТ_1]` |
| модель | Видит **только метки**. Исходных значений в запросе нет — это видно в аудит-логе |
| `outlet` | Метки в ответе модели заменяются исходными значениями (с учётом русской морфологии: «его супруга [ФИО_3]» → «Белоусова») |

Поддерживаются: `docx`, `docm`, `pdf`, `txt`, `md`.

Офисные форматы `xlsx`, `xlsm`, `pptx`, `pptm`, `odt`, `ods`, `odp` и бинарный
`doc` (Word 97–2003) тоже обезличиваются: текст из них извлекает сервис
(`references/office_extract.mjs`), ядро обезличивает этот текст, а пользователь
видит восстановленные значения. Подробности — в разделе «Какие форматы
поддерживаются».

Блокируются (fail-closed) только форматы, которые не читает ни ядро, ни сервис
(`.zip`, `.rar` и прочие бинарники): обезличить их нечем, а персональные данные
внутри возможны. Медиа (`png`, `jpg`, `mp3`, `mp4`) проходят как есть и обычные
чаты не ломаются.

## Какие форматы поддерживаются

| Формат | Кто извлекает текст | Результат |
|---|---|---|
| `docx`, `docm` | ядро | обезличивается целиком, включая таблицы и колонтитулы |
| `pdf` | ядро | обезличивается текстовый слой (для сканов и PDF без текста — нет OCR) |
| `txt`, `md` | ядро | обезличивается текст |
| `xlsx`, `xlsm` | сервис | разбираются ячейки и общие строки; текст обезличивается |
| `pptx`, `pptm` | сервис | разбираются слайды и заметки докладчика |
| `odt`, `ods`, `odp` | сервис | разбирается OpenDocument (`content.xml`) |
| `doc` (Word 97–2003) | сервис (LibreOffice) | бинарный OLE2 конвертируется в текст и обезличивается |
| `png`, `jpg`, `mp3`, `mp4` | — | проходят как есть, текстовых ПДн нет |
| `.zip`, `.rar`, прочие бинарники | — | **блокируются** (fail-closed) |

Почему извлечение делает сервис, а не Open WebUI: у Open WebUI `.odt` упирается в
его Pandoc (в sandbox-режиме Pandoc не находит свои data-файлы), а бинарный
`.doc` требует LibreOffice, которого в контейнере нет. Собственные разборы
сервиса не зависят от версии и настроек Open WebUI.

Одна оговорка: в `xlsx`/`pptx`/`odt`/`doc` нет структуры документа, контекста
меньше, чем в DOCX. Ядро опознаёт номер паспорта **по лейблу**
(«паспорт 45 05 123456» → `[ПАСПОРТ_1]`), без лейбла число не распознаётся —
это политика ядра. Для таблиц и презентаций результат стоит проверять вручную.

## Требования

- Open WebUI (проверено на `v0.12.0`)
- Хост с docker и интернетом (SSH-доступ нужен для установки)
- Node.js в контейнере сервиса (ставится через образ `node:22-alpine`)

Ядро обезличивания — [argmaster-dev/docx-anonymizer](https://github.com/argmaster-dev/docx-anonymizer)
(MIT). Этот репозиторий — обёртка: HTTP-сервис вокруг ядра и Filter для Open WebUI.

## Настройка: переключатели

Все переключатели — в настройках фильтра: **Админ → Functions →
docx_anonymizer → иконка шестерёнки (Valves)**. Каждый независим; значение
«как в сервисе» означает «взять настройку сервиса» (`DOCX_ANON_*`).

| Переключатель | Значения | Что делает |
|---|---|---|
| `COMMERCIAL` | включено / выключено / как в сервисе | группа `commercial` (названия организаций, номера договоров, суммы) |
| `MODE` | Метки / Звёздочки / Удалить / как в сервисе | форма замены: `[ФИО_1]` / `XXXXXX` / `[удалено]` |
| `NER_ENABLED` | включено / выключено / как в сервисе | модель распознавания имён и организаций |
| `NER_THRESHOLD` | 0.5 / 0.7 / 0.85 / 0.95 / как в сервисе | порог уверенности NER |
| `GOV_ENTITIES` | Не трогать / Маскировать / как в сервисе | госорганы и банки из списка ядра (`ФНС`, `МВД`, `Сбербанк`…) |
| `DICT_NAMES` | включено / выключено / как в сервисе | словарный детектор ФИО третьих лиц |
| `KEEP_METADATA` | Оставлять / Вычищать / как в сервисе | метаданные DOCX (`docProps`: автор, компания, время правки) |
| `STRIP_EMBEDDED` | Вырезать / Оставлять / как в сервисе | встроенные OLE-объекты и диаграммы |
| `PLACEHOLDER_LANGUAGE` | ru / en / как в документе / как в сервисе | язык меток: `[ФИО_1]` или `[PERSON_1]` |
| `LANGUAGE` | ru / en / both / как в документе / как в сервисе | язык распознавания |

Персональные данные и реквизиты (`pii`, `ids`: ФИО, паспорт, телефон, адрес,
ИНН, ОГРН, счета) маскируются **всегда**, в любом режиме — переключатель
`COMMERCIAL` на них не влияет.

Действуют на все форматы, включая xlsx/pptx/odt/doc.

При установке из скрипта можно задать значения сразу:

```bash
COMMERCIAL=Выключено MODE=Звёздочки NER_ENABLED=Выключено bash scripts/deploy_openwebui.sh
```

Если переменная не задана, выбор из интерфейса сохраняется — деплой его не
сбрасывает (update заменяет объект Valves целиком, поэтому деплой сначала
читает текущие значения и мержит с ними).

### Важные ограничения

- **Значения фильтра кэшируются в процессе Open WebUI**
  (`utils/filter.py`). После смены настройки в интерфейсе контейнер нужно
  перезапустить, иначе фильтр продолжит работать со старым значением. Скрипт
  установки перезапускает контейнер сам.
- **`MODE=Звёздочки` и `MODE=Удалить` необратимы**: значение не попадает в
  карту замен, поэтому восстановление в ответе не сработает. Для сценариев, где
  ответ должен содержать настоящие данные, нужен `MODE=Метки`.
- **`GOV_ENTITIES` при включённом NER**: правило ядра действует только на
  правиловый детектор компаний, а модель NER маскирует госорганы сама. Сервис
  делает пост-фильтрацию карты замен, чтобы «Не трогать» работал в обоих
  случаях.

## Установка

```bash
git clone <this-repo> && cd <this-repo>
bash scripts/deploy_openwebui.sh
```

**Подробная пошаговая инструкция (для человека и для ИИ-агента) —
[INSTALL.md](INSTALL.md).**

Скрипт идемпотентный — его можно запускать повторно, он обновляет, а не ломает.

Он делает следующее:

1. клонирует ядро upstream **на теге `v0.4.0`** в `/opt/docx-anon-service/repo`
   и ставит зависимости (`npm ci`);
2. скачивает модель распознавания персональных данных (ONNX, ~30 МБ) в `/opt/docx-anon-service/ner`;
3. тянет готовый образ сервиса `ghcr.io/zhenyarus39/owui-docx-anonymizer-service:latest`
   (в нём уже есть LibreOffice для `.doc`); если реестр недоступен — собирает
   образ локально (на 5–10 минут дольше);
4. поднимает контейнер `docx-anon-service` (`--network host`,
   `--restart unless-stopped`) с HTTP-сервисом на порту `8971`;
5. создаёт admin API-ключ Open WebUI и регистрирует Filter `docx_anonymizer`;
6. включает Filter и делает его глобальным;
Ожидаемый финал:

```
=== ГОТОВО
Проверка: curl http://127.0.0.1:8971/health
Фильтр: docx_anonymizer (active + global)
```

> **Версия ядра зафиксирована на `v0.4.0`.** В `v0.5.0` upstream поменял API
> ядра (`adapterForKind`/`parsePackage` вместо `parseDocx`/`serializeDocx`),
> и фильтр с ним не работает. Не меняй `CORE_VERSION` без проверки.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HA_HOST` | `192.168.1.4` | хост с Open WebUI |
| `HA_USER` | `root` | пользователь SSH |
| `HA_ROOT_PASSWORD` | — | пароль root для SSH |
| `BASE` | `/opt/docx-anon-service` | каталог установки на хосте |
| `PORT` | `8971` | порт сервиса обезличивания |
| `OWUI_CONTAINER` | определяется автоматически | контейнер Open WebUI |
| `OWUI_URL` | `http://127.0.0.1:8080` | адрес Open WebUI внутри хоста |
| `FILTER_ID` | `docx_anonymizer` | id функции-фильтра |
| `SKIP_LIVE_CHECK` | `0` | `1` — не гонять живую проверку в конце |
| `CORE_VERSION` | `v0.4.0` | версия ядра upstream |
| `GHCR_IMAGE` | `ghcr.io/zhenyarus39/owui-docx-anonymizer-service:latest` | образ сервиса |

### Ручная установка

1. `git clone --depth 1 https://github.com/argmaster-dev/docx-anonymizer.git /opt/docx-anon-service/repo`
   и `npm ci` внутри (там `onnxruntime-web` и `pdfjs-dist` — без них не работает ни NER, ни PDF).
2. Модель NER: zip из [релизов upstream](https://github.com/argmaster-dev/docx-anonymizer/releases)
   в `/opt/docx-anon-service/ner` (нужен файл `model.onnx`).
3. `references/anon_service.mjs` → `/opt/docx-anon-service/anon/`,
   `scripts/anonymize.mjs` → `/opt/docx-anon-service/anon/scripts/`.
4. Контейнер:

   ```bash
   docker run -d --name docx-anon-service-8971 \
     --network host --restart unless-stopped \
     -v /opt/docx-anon-service/repo:/srv/repo:ro \
     -v /opt/docx-anon-service/ner:/srv/ner:ro \
     -v /opt/docx-anon-service/anon:/srv/anon:ro \
     -v /opt/docx-anon-service/state:/srv/state \
     -e DOCX_ANON_REPO=/srv/repo -e DOCX_ANON_NER=/srv/ner \
     -e DOCX_ANON_WRAPPER=/srv/anon/scripts/anonymize.mjs \
     -e DOCX_ANON_WORKDIR=/srv/state -e DOCX_ANON_PORT=8971 \
     -w /srv/anon node:22-alpine node /srv/anon/anon_service.mjs
   ```

5. Filter: `references/openwebui-filter.py` — как функция с id `docx_anonymizer`,
   `is_active=true`, `is_global=true`. Значения `Valves` — дефолтные
   (`SERVICE_URL=http://127.0.0.1:8971`): сервис доступен по localhost, потому что оба
   контейнера в host-network.

Проверка:

```bash
curl -s http://127.0.0.1:8971/health
# {"ok":true,"ner":true,"repo":"/srv/repo",...}
```

## Проверка

### Сервис отвечает

```bash
curl -s http://127.0.0.1:8971/health
# {"ok":true,"ner":true,"repo":"/srv/repo",...}
```

### В чате

Загрузите в чат документ с персональными данными и попросите перечислить ФИО:

- модель должна видеть **метки** (`[ФИО_1]`, `[ПАСПОРТ_1]`), а не исходные значения;
- в ответе пользователю значения должны быть **восстановлены**;
- документ неподдерживаемого формата (`.zip`) не должен уйти к модели — вместо
  ответа должна быть плашка, что файл не передан;
- то же самое должно работать для `.xlsx`, `.pptx`, `.odt` и `.doc`: модель видит
  метки, пользователь — восстановленные значения.

## Устройство

```
references/openwebui-filter.py   Filter Open WebUI: inlet (обезличить) + outlet (восстановить)
references/anon_service.mjs      HTTP-сервис: /health, /anonymize, /extract, /restore
references/office_extract.mjs     извлечение текста из xlsx/pptx/odt/doc (свой разбор + LibreOffice)
references/settings.md           справка по настройкам ядра
scripts/anonymize.mjs            CLI-обёртка над ядром (anonymize / restore)
scripts/deploy_openwebui.sh      установка и обновление на хосте
docs/DEVELOPMENT.md          журнал разработки: как устроен Filter, подводные камни Open WebUI
```

### Что лежит в `body` в момент `inlet`

`body["files"]` — список вложений, `body["messages"]` — сообщения, `body["metadata"]` —
метаданные чата. Содержимого файла там **нет**: обезличивать нужно самому —
скачать, обработать, подменить.

Имя параметра хука — `__user__`, не `user` (в шаблоне Filter в UI Open WebUI — баг шаблона).

### Порядок работы в Open WebUI

`middleware.py` добавляет блок `<attached_files>` с id файла **до** `inlet`.
По этому id модель может вызвать встроенный инструмент `view_file` и прочитать
оригинал. Поэтому Filter не только чистит `body["files"]`, но и:

1. вырезает блок `<attached_files>` из текста сообщения;
2. перезаписывает `files.data['content']` обезличенным текстом.

Без этого ПДн утекли бы через `view_file`, RAG и поиск по коллекции.
